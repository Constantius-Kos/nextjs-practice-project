# Урок 24: Middleware та Advanced Routing 🛡️

## 1. Що таке Middleware?
**Middleware** — це спеціальний файл, який виконується **ПЕРЕД** тим, як запит потрапить до будь-якої сторінки, API-роуту або статичного файлу.

Це "охоронець" на вході до твого додатка. 

### Як це працює:
Користувач тисне на лінк `/dashboard` -> Запит перехоплює **Middleware** -> Він перевіряє сесію -> Якщо ок, пускає далі. Якщо ні — миттєво відправляє на `/login`.

## 2. Основні характеристики Middleware в Next.js:
1.  **Файл**: Має називатися `middleware.ts` і лежати в **корені проекту** (поруч з `app/` або всередині `src/`).
2.  **Runtime**: Працює на **Edge Runtime**. Це означає, що він супер-швидкий, але має обмеження (не можна використовувати стандартні Node.js бібліотеки типу `fs`, тільки обмежений набір Web APIs).
3.  **Matcher**: Дозволяє вказати, на які саме шляхи має спрацьовувати Middleware.

## 3. Навіщо він потрібен?
*   **Автентифікація**: Захист адмін-панелі або приватних сторінок.
*   **Redirects & Rewrites**: Наприклад, перенаправлення застарілих посилань.
*   **Headers**: Додавання кастомних HTTP-заголовків.
*   **i18n**: Визначення мови користувача за його локацією або куками.
*   **A/B тестування**: Покази різних версій сторінок різним користувачам.

## 4. Базовий синтаксис
```typescript
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function middleware(request: NextRequest) {
  // Логіка перевірки
  return NextResponse.next() // Пропустити запит далі
}

// Конфігурація для фільтрування шляхів
export const config = {
  matcher: '/dashboard/:path*',
}
```
