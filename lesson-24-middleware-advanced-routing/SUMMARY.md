# Резюме уроку 24: Middleware & Advanced Routing

У цьому уроці ми опанували роботу з Middleware — потужним інструментом Next.js для перехоплення запитів на "межі" (Edge) між сервером та клієнтом.

## Основні тези:
- **Місцезнаходження**: Файл `middleware.ts` має бути ТІЛЬКИ в корені проекту або в папці `src/`.
- **Edge Runtime**: Middleware працює в обмеженому, але надшвидкому середовищі. Тут недоступні Node.js API (н-ад: `fs`, `path`) та важкі ORM (н-ад: `prisma`).
- **Matcher**: Дозволяє фільтрувати запити, на які буде спрацьовувати логіка, економлячи ресурси. Підтримує масиви та регулярні вирази.
- **Парадигма Response**: Будь-яка дія (`next()`, `redirect()`, `rewrite()`) має бути повернута через `return`.

## Що зроблено в практиці:
1.  **Захист доступу**: Реалізовано перевірку Auth.js сесії (`authjs.session-token`) з автоматичним редиректом на головну сторінку.
2.  **Маніпуляція хедерами**: Навчилися створювати нові хедери та прокидати їх у Server Components через `NextResponse.next({ request: { headers } })`.
3.  **Bot Detection**: Реалізовано перевірку `user-agent` для ідентифікації та перенаправлення ботів.
4.  **Безпека**: Використано конструктор `new URL()` для створення надійних абсолютних шляхів редиректу.

## Корисні поради:
- Завжди використовуйте `matcher`, щоб не "гальмувати" статичні файли (картинки, стилі).
- Для складних перевірок аутентифікації краще використовувати `auth` як обгортку в middleware (Auth.js v5).
