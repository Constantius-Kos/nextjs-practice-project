# 📝 Нотатки Уроку 9: fetch() та Кешування

### Запитання та відповіді

**Запитання:** Синтаксис `fetch` в Next.js: як об'єднувати стандартні настройки (headers, method) та специфічні параметри кешування?
**Відповідь:** Next.js розширює стандартний об'єкт налаштувань `fetch`. Всі стандартні поля (`method`, `headers`, `body`) пишуться на верхньому рівні об'єкта, а специфічні налаштування Next.js (наприклад, `revalidate`) групуються всередині спеціального поля `next`.
Приклад:
```ts
fetch(url, {
  method: 'GET',
  headers: { 'Content-Type': 'application/json' },
  next: { revalidate: 3600 }
})
```
**Запитання:** Де ми бачимо `console.log`, написаний у Server Component?
**Відповідь:** Тільки в терміналі сервера (VS Code), оскільки код виконується на сервері до того, як HTML потрапить у браузер.

**Запитання:** Що буде, якщо змінити дані в API, коли встановлено `revalidate: 10`?
**Відповідь:** Якщо з моменту останнього запиту пройшло менше 10 секунд, Next.js віддасть старі дані з кешу. Тільки після завершення цього вікна наступний запит оновить кеш.

**Запитання:** Чи можна використовувати `await fetch()` в тілі Client Component?
**Відповідь:** Ні. Клієнтські компоненти не можуть бути асинхронними (`async`). Для отримання даних там все ще потрібен `useEffect` або спеціальні хуки (наприклад, `use` в React 19, але це інша історія).
