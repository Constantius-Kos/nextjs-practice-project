# 📋 Резюме уроку 8: fetch() та Кешування

### 1. Data Fetching у Server Components
- Next.js дозволяє робити компоненти асинхронними: `async function Page() { ... }`.
- Можна використовувати **`await fetch()`** прямо в тілі компонента. Весь SQL-запит або API-запит відбудеться на сервері, а клієнт отримає вже готовий HTML.

### 2. Агресивне Кешування
- Next.js за замовчуванням запам'ятовує результат кожного `fetch()`. Якщо ти зайдеш на сторінку вдруге — дані не будуть завантажуватись знову, а підтягнуться з кешу. Це робить сайт неймовірно швидким.

### 3. Ревалідація (Оновлення даних)
Якщо дані змінюються, ми можемо сказати Next.js, коли оновити кеш:
- **Часова ревалідація**: `fetch(..., { next: { revalidate: 3600 } })` — оновлювати раз на годину.
- **Динамічна робота**: `{ cache: 'no-store' }` — завжди завантажувати нові дані (корисно для цін або залишків на складі).

### 4. Новинка Next.js 16: "use cache"
- Це нова директива для кешування цілих функцій. Вона замінює старі складні механізми. Просто додаєш рядок `'use cache'` зверху асинхронної функції — і її результат буде закешований.

### 5. Безпека
- Оскільки `fetch` відбувається на сервері, твої API-токени та внутрішні адреси баз даних ніколи не потраплять в код браузера користувача. Дивитись на `console.log` серверних компонентів потрібно в терміналі розробника, а не в інспекторі браузера.
