# 📋 Резюме уроку 14: Cache Tags & Invalidation (Інвалідація кешу)

### 1. Invalidation (Інвалідація) — очищення кешу
- Повідомлення сервера про те, що закешовані дані застаріли.
- Next.js не оновлює дані сам, поки ми не дамо команду або не закінчиться час.

### 2. Теги (Tags) 🏷️
- **`cacheTag('назва')`**: Наклеює "стікер" на блок даних всередині `"use cache"`.
- До однієї функції можна додати багато тегів (наприклад, `user-1`, `all-users`).

### 3. Методи оновлення
- **`updateTag('назва')`**: Миттєве видалення кешу. Наступний запит БЛОКУЄТЬСЯ до отримання нових даних. Найкраще для Server Actions.
- **`revalidateTag('назва', 'max')`**: Фонове оновлення. Користувач бачить старе (Stale), поки сервер готує нове (Revalidate). Пріоритет на швидкість (SWR).
- **`revalidatePath('/')`**: Очищення всього контенту на конкретній сторінці або у всьому додатку.

### 4. Синхронізація UI (Server vs Client) 🔄
- Очищення кешу на сервері (`updateTag`) не скидає автоматично **Error Boundary** або **Not Found** у браузері.
- Для повного оновлення треба використовувати **`reset()`** (у файлі помилки) або **`router.refresh()`** (для всього роутера).

---

### 💡 Ключові висновки нашої практики:
1.  **Липкі помилки**: Стан помилки в браузері — "липкий". Щоб його прибрати після очищення кешу, треба викликати `reset()`.
2.  **Next.js 16**: Вимагає профілі для `revalidateTag`. Якщо використовувати застарілий синтаксис з одним аргументом — виникне помилка типів.
3.  **Екшени**: Використання `updateTag` всередині Server Actions — це стандарт для отримання свіжих даних відразу після дії користувача.
