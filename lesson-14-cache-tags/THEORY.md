# 📖 Теорія Уроку 14: Керування свіжістю кешу (Invalidation)

В Уроці 13 ми навчилися створювати "вічний" кеш за допомогою `"use cache"`. Це круто для швидкості, але жахливо для динамічних сайтів, де дані змінюються (наприклад, ціна товару, лічильник лайків або назва проєкту). 

Сьогодні ми вивчаємо **Invalidation (Інвалідацію)** — процес повідомлення Next.js про те, що закешовані дані більше не актуальні.

---

### 1. 🏷️ cacheTag("назва-тега") — Маркування даних

Це як наклеїти стікер на коробку в коморі. Поки на коробці є стікер, ми знаємо, що там лежить. Використовується **тільки** всередині функцій з `"use cache"`.

*   **Навіщо це треба:** Один і той самий тег можна додати до різних функцій. Наприклад, тег `user-123-data` можна додати і до функції `getProfile(123)`, і до `getPosts(123)`.
*   **Синтаксис:**
    ```tsx
    import { cacheTag } from 'next/cache';

    async function getUserData(id: string) {
      "use cache";
      cacheTag(`user-${id}`); // Клеїмо динамічний тег
      return db.user.findUnique({ where: { id } });
    }
    ```

---

### ⚡ 2. revalidateTag("назва-тега", "max") — Новий стандарт
У Next.js 16 `revalidateTag` вимагає другого аргументу (профілю).
- **`revalidateTag(tag, 'max')`** — позначає кеш як застарілий. Користувач побачить старі дані, а оновлення відбудеться у фоні.

### 🚀 3. updateTag("назва-тега") — Для Server Actions
Це нова функція, яка ідеально підходить для нашого випадку. Вона видаляє кеш **миттєво**.
- **Коли використовувати:** Тільки в Server Actions, коли ви точно знаєте, що дані змінилися і юзер має побачити нові результати негайно.

---

### 🗺️ 3. revalidatePath("шлях") — Прибирання за територією

Замість того, щоб шукати стікери, ми просто кажемо: "Очисть усе, що стосується цієї адреси".

*   **Варіанти:**
    *   `revalidatePath('/dashboard')` — очистить кеш тільки для цієї сторінки.
    *   `revalidatePath('/blog/[slug]', 'page')` — очистить конкретну динамічну сторінку.
    *   `revalidatePath('/', 'layout')` — радикальний метод, очищує кеш всього додатку.
*   **Коли використовувати:** Коли змін забагато або ви не хочете створювати складну систему тегів.

### 💡 Лайфхаки для Next.js 16 (On-demand Revalidation)

1.  **Multi-tagging:** Ви можете додавати кілька тегів до однієї функції: `cacheTag("all-users", "user-1")`. Тоді ви зможете оновити або конкретного юзера, або всіх відразу.
2.  **Ніколи не оновлюйте кеш "про всяк випадок":** Кожна інвалідація змушує сервер працювати. Оновлюйте тільки тоді, коли дані реально змінилися.
3.  **Автоматизація:** Якщо ваш додаток — це адмін-панель, краще використовувати теги. Якщо це лендінг — вистачить і `revalidatePath`.

---

### ⚠️ Типові помилки новачка:

*   **Забув імпорт:** `cacheTag` та `revalidateTag` живуть у пакеті `next/cache`.
*   **Оновлення без тега:** Викликати `revalidateTag`, але забути додати `cacheTag` у функцію отримання даних. Ефекту буде нуль.
*   **Друкарські помилки:** Якщо в `cacheTag` написано `"users"`, а в `revalidateTag` — `"user"`, нічого не спрацює. Використовуйте константи, якщо тегів багато.

### ✍️ Практика

#### Задача 1: Маркування (Warm-up)
Відкрий `app/(main)/dashboard/getCachedData.ts`.
- Імпортуй `cacheTag` з `next/cache`.
- Додай тег `"dashboard-data"` всередину функції.

#### Задача 2: Server Action (Main)
Створи файл `app/(main)/dashboard/actions.ts`.
- Додай директиву `"use server"`.
- Напиши асинхронну функцію `refreshDashboardData()`.
- Всередині викличи **`updateTag("dashboard-data")`**.

#### Задача 3: Інтеграція (Challenge)
В одному з компонентів дашборду (наприклад, у кнопці оновлення):
- Додай кнопку "Оновити дані".
- Викликай свій Server Action при кліку.
- **Перевірка:** Після кліку сторінка має "задуматись" на 3 секунди (як у коді) і показати нові дані (якщо ти зміниш return у функції).
