# Урок 3: Server Components vs Client Components

## 🎯 Мета уроку
- Глибоко зрозуміти «межі» (boundaries) між сервером і клієнтом
- Навчитись правильно передавати дані між ними
- Зрозуміти, чому Server Components — це стандарт за замовчуванням

---

## 📖 Теорія

### Чому Server Components (SC) — це круто?
1. **Швидкість:** Код виконується ближче до даних (на сервері).
2. **Безпека:** Можна писати SQL-запити або використовувати API-ключі прямо в компоненті.
3. **Менше JS:** Браузер не завантажує код SC. Якщо у тебе в SC є величезна бібліотека на 200кб для обробки тексту — користувач її НЕ завантажить.

### Коли використовувати Client Components (CC)?
- Коли є `useState` або `useReducer`.
- Коли є `useEffect` або `useLayoutEffect`.
- Коли треба звертатись до браузерних API (`window`, `document`, `localStorage`).
- Коли є обробники подій (`onClick`, `onChange`).

---

## 💡 Головні правила «Межі»

### 1. Зверху вниз
Server Component МОЖЕ імпортувати Client Component.

```tsx
// Server
import ClientComp from './ClientComp'
export default function Page() {
  return <ClientComp /> // ✅ ТАК
}
```

### 2. Але НЕ навпаки
Client Component НЕ МОЖЕ імпортувати Server Component прямо.

```tsx
'use client'
import ServerComp from './ServerComp' // ❌ ТАК НЕ МОЖНА
```
*(Хоча є лайфхак з `children`, про який ми згодом поговоримо)*

### 3. Серіалізація
Коли Server Component передає дані в Client Component через `props` — ці дані мають бути **серіалізованими** (рядки, числа, об'єкти, масиви). 
Ви НЕ МОЖЕТЕ передати функцію з сервера на клієнт таким чином.

## ✍️ Завдання на розуміння:

1. Створити інтерактивний компонент з `'use client'`.
2. Вставити його в серверну сторінку.
3. Спробувати передати дані з сервера (наприклад, заголовок сторінки) в цей клієнтський компонент через пропси.
