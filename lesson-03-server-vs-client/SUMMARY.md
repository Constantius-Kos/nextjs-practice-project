# 📋 Резюме уроку 3: Server Components vs Client Components

### 1. Переваги Server Components (SC)
- **Продуктивність**: Код виконується на сервері, браузер отримує чистий HTML без зайвого JS.
- **Безпека**: Можна використовувати секретні токени, API-ключі та робити прямі запити до бази даних прямо в компоненті.
- **Zero Bundle Size**: Величезні бібліотеки (наприклад, для парсингу Markdown) не відправляються клієнту, якщо вони використовуються в SC.

### 2. Коли переходити на Client Components (CC)?
Використовуй `'use client'`, якщо тобі потрібні:
- **Hooks**: `useState`, `useEffect`, `useReducer`.
- **Browser API**: `window`, `document`, `localStorage`, `geolocation`.
- **Event Handlers**: Атрибути `onClick`, `onChange`, `onSubmit` тощо.

### 3. Золоте правило «Межі» (Boundary)
- **Зверху вниз**: Server Component може імпортувати і відображати Client Component.
- **Але не навпаки**: Клієнтський компонент НЕ може імпортувати серверний. 
- **Лайфхак**: Якщо треба показати серверний компонент всередині клієнтського — передай його як **`children`** або інший пропс.

### 4. Серіалізація даних
- Дані, які SC передає в CC через пропси, мають бути "серіалізованими" (рядки, масиви, прості об'єкти).
- **Функції** передавати з сервера на клієнт не можна — вони не можуть бути передані через мережу як дані.

### 5. Чому Next.js вибирає Сервер?
По замовчуванню все є Server Component, щоб твій додаток був максимально легким для браузера. Клієнтський режим вмикається "точково" тільки там, де без нього ніяк.
