# Урок 25: Environment Variables (Змінні оточення) 🔐

## 1. Навіщо вони потрібні?
Кожен серйозний додаток має секрети: ключі до API, паролі від бази даних, секретні фрази для сесій. 
Ми не можемо писати їх прямо в коді, бо:
1. Це небезпечно (хто завгодно в Git побачить пароль).
2. Налаштування відрізняються (на комп'ютері одна база, на сервері — інша).

## 2. Файли налаштувань у Next.js
Next.js автоматично шукає змінні у таких файлах:
- `.env` — загальні налаштування для всіх.
- `.env.local` — тільки для твого комп'ютера (ігнорується Git). **Найважливіший файл!**
- `.env.development` та `.env.production` — для відповідних режимів.

## 3. Головне правило: Сервер vs Клієнт
За замовчуванням усі змінні в `.env` доступні **ТІЛЬКИ на сервері** (Server Components, Route Handlers, Middleware). У браузер (Client Components) вони не потрапляють заради безпеки.

Але якщо тобі ТРЕБА показати щось клієнту (наприклад, публічний ключ Google Maps), ти маєш додати префікс:
- `API_KEY=123` (Сервер-онлі)
- `NEXT_PUBLIC_API_KEY=ABC` (Доступно і на сервері, і в браузері)

## 4. Як використовувати в коді
Ми звертаємось до них через об'єкт `process.env.НАЗВА_ЗМІННОЇ`.

**Важливо:** У Next.js 16/React 19 змінні оточення під час рендерингу статичних сторінок можуть "зашиватися" в код, тому для динамічних значень іноді використовують спеціальні методи, але `process.env` залишається основою.

## 5. Безпека
Завжди тримай `.env.local` у файлі `.gitignore`. Файл `.env.example` зазвичай створюють як шаблон з пустими значеннями для інших розробників.
