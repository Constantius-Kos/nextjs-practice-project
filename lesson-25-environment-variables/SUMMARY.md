# Резюме уроку 25: Environment Variables

У цьому уроці ми навчилися безпечно керувати налаштуваннями та секретами додатка за допомогою змінних оточення в Next.js.

## Основні тези:
- **Типи файлів**: 
    - `.env.local`: Приватні налаштування (не йдуть у Git).
    - `.env.example`: Шаблон для команди (йде у Git).
- **Межі клієнт/сервер**: За замовчуванням змінні доступні лише на сервері. Для доступу в браузері обов'язково використовувати префікс `NEXT_PUBLIC_`.
- **Помилки гідратації**: Використання серверних змінних у Client Components призводить до `Hydration Error`, оскільки значення на сервері (існує) відрізняється від значення в браузері (undefined).

## Що зроблено в практиці:
1.  **Налаштування секретів**: Створено `.env.local` з тестовим секретом.
2.  **Тестування Hydration**: На власному досвіді побачили помилку при спробі вивести серверний секрет у `'use client'` компоненті.
3.  **Публічні змінні**: Реалізовано вивід версії додатка через `NEXT_PUBLIC_`.
4.  **Командна робота**: Створено `.env.example` для зручного клонування проекту іншими розробниками.

## Порада на майбутнє:
Завжди перевіряйте наявність критичних змінних (наприклад, `DATABASE_URL`) на старті додатка, щоб уникнути незрозумілих помилок у production.
