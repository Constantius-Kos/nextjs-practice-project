# 📖 Теорія Уроку 15: Керування часом (SSG, SSR та ISR 2.0)

У Next.js 16 ми відходимо від налаштування "секунд" у феч-запитах. Краще думати про **наміри** (intents). Замість "кешуй на 60 секунд", ми кажемо "кешуй цей блок так, ніби це стрічка новин, яка оновлюється часто".

---

### 1. 🕒 cacheLife — Нове серце ISR

Функція `cacheLife` керує тим, як довго дані залишаються "свіжими" (Fresh) і коли вони стають "застарілими" (Stale).

*   **Fresh (Свіжі):** Дані віддаються миттєво з кешу. Сервер навіть не "прокидається".
*   **Stale (Застарілі):** Час вийшов. Next.js віддасть користувачу ці старі дані **останній раз**, але одночасно запустить фонове оновлення.
*   **Expired (Протухлі):** Дані видаляються зовсім. Наступний юзер чекатиме на повний рендер (Blocking).

---

### 2. 🎯 Стандартні профілі (Presets)

Next.js 16 пропонує використовувати іменовані пресети. Це робить код читабельним:

| Профіль | Орієнтовний час | Приклад використання |
| :--- | :--- | :--- |
| **`'seconds'`** | 1 - 60 сек | Котирування валют, лічильник переглядів. |
| **`'minutes'`** | 5 - 60 хв | Список останніх постів, погода. |
| **`'hours'`** | 1 - 24 год | Статті в блозі, документація. |
| **`'days'`** | 1 - 7 днів | Налаштування сайту, футер. |
| **`'weeks'`** | 7+ днів | Архіви, стара історія. |
| **`'max'`** | "Назавжди" | Майже як SSG, поки не скинемо тегом. |

---

### 🛠️ 3. Як налаштувати свої профілі в `next.config.ts`

Якщо стандартні пресети тобі не підходять, ти можеш створити свій:

```typescript
// next.config.ts
const nextConfig = {
  experimental: {
    cacheLife: {
      'poker-hands': {
        stale: 3600,    // свіжі 1 годину
        revalidate: 60, // оновлювати у фоні кожну хвилину після години
        expire: 86400,  // через добу видалити зовсім
      }
    }
  }
}
```
**Використання:** `cacheLife('poker-hands')`. Це набагато професійніше, ніж розкидати цифри по всьому коду.

---

### � 4. Формула Перемоги: Tags + Life

Найпотужніший прийом у Next.js 16 — це об'єднання часу та тегів:

```tsx
async function getProjectDetails(id: string) {
  "use cache";
  cacheTag(`project-${id}`); // Можемо скинути руками через Server Action
  cacheLife('hours');        // А якщо забудемо скинути — сам оновиться через добу
  
  return db.projects.findUnique({ where: { id } });
}
```
Це створює **багаторівневий захист**: твій сайт завжди швидкий, завжди актуальний, і ти маєш повний контроль.

### ✍️ Практика

#### Задача 1: Часовий кеш (ISR)
Відкрий `app/components/WelcomeCard.tsx`.
- Додай до нього `"use cache"`.
- Додай `cacheLife('seconds')`.
- Виведи поточний час: `new Date().toLocaleTimeString()`.
- **Перевірка:** Оновлюй сторінку кожні 2-3 секунди. Час має змінюватися не кожен раз, а приблизно раз на хвилину (або рідше, залежно від налаштувань пресета `seconds`).

#### Задача 2: Користувацький профіль (Challenge)
1. Додай у `next.config.ts` свій профіль `fast-cache` з параметром `stale: 10` (10 секунд).
2. Використай його у функції `getCachedData.ts`.
3. Переконайся, що через 10 секунд дані оновлюються автоматично.

Створи функцію, яка кешує "кількість активних юзерів" на 5 секунд через `cacheLife`, але має тег `analytics`. Спробуй натиснути свою стару кнопку "Оновити", щоб скинути цей кеш раніше, ніж минуть 5 секунд.
