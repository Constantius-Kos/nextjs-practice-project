# Notes: Lesson 27 — React Compiler

## ❓ Питання та відповіді

**П: React Compiler не мемоізує функції/змінні якщо вони мають зовнішні залежності?**
В: Якщо компілятор бачить, що код залежить від зовнішніх змінних або змінює їх (side effect), він відмовляється оптимізувати цей блок. Він знає, що `counter++` або `console.log` — це не чисте обчислення. Natomiast компілятор просто "пропускає" цей компонент — помилки не буде, просто мемоізація не застосовується.

**П: Функції/змінні що не підходять під правила — просто не кешуються і будуть виконуватись заново? Чи буде помилка?**
В: Помилки не буде. Компілятор тихо робить "bail-out" — компонент залишається як звичайний React-компонент. Програма не зламається, але приросту швидкості не буде.

**П: Якщо огорнути в useMemo — лог всередині та console.log перестане з'являтися?**
В: `console.log` всередині `useMemo` — антипатерн. `useMemo` для чистих обчислень без side effects. Крім того, React Compiler може "переписати" або проігнорувати зайві useMemo, якщо він вже керує мемоізацією.

**П: Чому з useMemo([]) лог все одно з'являється при кожному кліку?**
В: `console.log` — це side effect. React та React Compiler не гарантують кешування блоку з side effects. Правильний тест — перевірка через React DevTools (значок `Memo ✨`), а не через console.log.

## 🔑 Ключові відкриття сесії

1. **React Compiler активний** — підтверджено значком `Memo ✨` у React DevTools (вкладка Components) в production збірці.
2. **`reactCompiler: true` — параметр верхнього рівня** у Next.js 16.2.5, НЕ всередині `experimental`.
3. **console.log — поганий інструмент для тесту мемоізації**: компілятор свідомо не кешує блоки з side effects.
4. **Правильний індикатор роботи компілятора** — React DevTools → Components → значок `✨ Memo (Compiler)`.
5. **`reactStrictMode: false`** додано в конфіг для усунення подвійних рендерів у dev режимі.
