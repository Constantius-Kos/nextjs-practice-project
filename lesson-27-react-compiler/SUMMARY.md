# Урок 27: React Compiler — Майбутнє мемоізації

У цьому уроці ми розібралися з революційною зміною в екосистемі React — автоматичною мемоізацією через React Compiler у Next.js 16.

### 🎯 Результати уроку:
1.  **Активація Compiler**: Навчили Next.js використовувати компілятор через `reactCompiler: true`.
2.  **Детекція ре-рендерів**: Створили тестовий стенд для перевірки, де мемоізація працює, а де — ні.
3.  **Розуміння Bail-out**: З'ясували, що компілятор дуже чутливий до чистоти коду (Side effects, як `console.log`, змушують його відмовлятися від оптимізації).
4.  **Смерть useMemo/useCallback**: Зрозуміли, що ці хуки тепер стають опціональними "реліктами", оскільки компілятор справляється краще і без накладних витрат на порівняння залежностей.

### 🛠 Ключові концепції:
- **Auto-memoization**: Компілятор перетворює звичайний код на оптимізований "під капотом", кешуючи результати обчислень та JSX вузли.
- **✨ Memo (Compiler)**: Спеціальний статус у React DevTools, який підтверджує успішну оптимізацію.
- **Чисті компоненти**: Вимога до чистоти функцій стає критичною — компілятор працює тільки з передбачуваним кодом.

### 🏁 Статус проекту:
- Режим розробки працює з увімкненим компілятором.
- `Counter.tsx` та `StaticComponent.tsx` успішно оптимізовані (перевірено через DevTools).
- Конфігурація `next.config.ts` оновлена.
