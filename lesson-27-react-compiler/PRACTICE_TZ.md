# Практика: Урок 27 — React Compiler

Сьогодні ми проведемо експеримент: створимо компонент, який "гальмує", і подивимось, як React Compiler виправляє ситуацію без жодного `useMemo`.

## Задача 1: Підготовка середовища
1. Відкрий `next.config.ts` (або `.js`).
2. Додай `reactCompiler: true` у секцію `experimental`.
3. Перезапусти сервер розробки (`npm run dev`).

## Задача 2: Детектор ререндерів (Розминка)
Створи сторінку `app/detect/page.tsx`:
1. Створи стан `count` (число) і кнопку для його збільшення.
2. Створи важкий обчислювальний блок прямо в тілі компонента:
   ```typescript
   console.log("=== Важкі обчислення виконуються! ===");
   const items = Array.from({ length: 10000 }).map((_, i) => i);
   ```
3. Виведи результат обчислень (наприклад, суму масиву).
4. **Спостереження:** Подивись у консоль браузера. Чи з'являється лог при кожному кліку на кнопку?

## Задача 3: Перевірка автоматичної мемоізації компонентів
1. Створи окремий компонент `StaticComponent.tsx`. Нехай він просто виводить текст: "Я статический, не рендери мене просто так". Додай всередину `console.log("StaticComponent Rendered")`.
2. Використай його на сторінці `app/detect/page.tsx`.
3. Клікай на кнопку `count`. 
4. **Питання:** Чи бачиш ти лог від `StaticComponent` у консолі? Якщо компілятор працює — логу бути не повинно!

## Задача 4: Челлендж — React DevTools "Candy"
1. Встанови (якщо немає) React DevTools у браузер.
2. Відкрий вкладку **Components**.
3. Знайди свою сторінку. Поруч із компонентами, які були оптимізовані компілятором, має з'явитися спеціальна позначка: ✨ **Memo (Compiler)**.
4. Переконайся, що твій код отримав цю магічну мітку.
