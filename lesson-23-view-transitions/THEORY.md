# Урок 23: View Transitions API — Повний посібник

## 1. Що таке View Transitions API?
**View Transitions API** — це нативний механізм браузера, який дозволяє створювати плавні переходи між різними станами інтерфейсу або між цілими сторінками (навігація).

Раніше для цього використовували важкі бібліотеки (наприклад, Framer Motion), які вручну відстежували позиції елементів та анімували їх через JavaScript. Тепер браузер робить це самостійно на рівні рендерингу.

## 2. Як це працює (Механіка "Знімка")
Коли ініціюється перехід, браузер виконує наступні кроки:
1. **Capture Old**: Робить віртуальний знімок (screenshot) поточної сторінки.
2. **Update DOM**: Next.js (або JS) замінює контент на новий.
3. **Capture New**: Робить знімок нової сторінки.
4. **Transition**: Створює тимчасову структуру з цих знімків і анімує перехід між ними за допомогою CSS.

## 3. Два типи навігації
*   **Same-document (SPA)**: Перехід в межах однієї сторінки (як у Next.js через `<Link>`). Потребує виклику `document.startViewTransition()`. У Next.js 16 це автоматизується через конфіг.
*   **Cross-document (MPA)**: Класичний перехід між файлами з перезавантаженням. Активується через CSS правило `@view-transition { navigation: auto; }`.

## 4. Ієрархія псевдоелементів
Коли працює перехід, браузер створює дерево псевдоелементів:
- `::view-transition` — корінь всього переходу.
    - `::view-transition-group(name)` — контейнер для конкретного елемента.
        - `::view-transition-image-pair(name)` — контейнер для "старого" та "нового" вигляду.
            - `::view-transition-old(name)` — "фотографія" старого елемента.
            - `::view-transition-new(name)` — "фотографія" нового елемента.

*Примітка:* `name` за замовчуванням — `root` (вся сторінка).

## 5. Основний синтаксис

### У CSS:
1. **Увімкнення переходу** (для MPA):
```css
@view-transition {
  navigation: auto;
}
```

2. **Ідентифікація елементів**:
Щоб браузер зрозумів, що "Ось цей заголовок" у списку і "Цей заголовок" на сторінці поста — це один і той самий об'єкт:
```css
.post-title {
  /* Важливо: ім'я має бути унікальним на сторінці! */
  view-transition-name: post-title-1;
}
```

3. **Кастомізація анімації**:
За замовчуванням браузер робить плавне розчинення (`opacity`). Ми можемо це змінити:
```css
::view-transition-old(root) {
  animation: slide-out 0.5s;
}
::view-transition-new(root) {
  animation: slide-in 0.5s;
}
```

## 6. Чому Next.js 16 — особливий?
Next.js використовує **Client-side routing**. Це означає, що коли ти тиснеш посилання, він не перезавантажує сторінку (MPA), а підміняє контент (SPA). 

Через це правило `@view-transition { navigation: auto; }` може не спрацювати саме по собі при кліках по `<Link>`. Next.js 16 має експериментальну підтримку, яка автоматично загортає навігацію в `document.startViewTransition`.

## 7. Переваги та обмеження
**Переваги**:
- **Продуктивність**: Анімації виконуються на GPU.
- **Доступність**: Браузер коректно працює з фокусом та скрінрідерами під час переходу.
- **Простота**: Мінімум JS, максимум CSS.

**Обмеження**:
- **Унікальність імен**: На одній сторінці не може бути двох елементів з однаковим `view-transition-name`.
- **Streaming & Suspense**: Якщо контент вантажиться частинами, це може призвести до скасування переходу (`AbortError`).
