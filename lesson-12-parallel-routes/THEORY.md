# 🟦 Урок 12: Parallel Routes (Паралельні маршрути)

### 🎯 Мета
Навчитися розділяти інтерфейс на незалежні слоти, які можуть завантажуватися паралельно та мати власну логіку обробки помилок.

---

### 📖 Теорія: Що це таке?
**Parallel Routes** дозволяють одночасно рендерити кілька сторінок в одному лейауті. Це робиться за допомогою спеціальних папок, які починаються з символу `@` (наприклад, `@analytics`, `@team`).

Ці папки називаються **Slots** (слоти).

#### Чому це важливо?
1. **Незалежний Streaming**: Кожен слот може мати свій `loading.tsx`. Один блок даних може вантажитися 1 секунду, інший — 5 секунд.
2. **Незалежні помилки**: Якщо один віджет на дашборді зламався, інша частина сторінки продовжить працювати (завдяки окремому `error.tsx`).
3. **Condition Rendering**: Ти можеш легко показувати або ховати слоти в `layout.tsx` на основі стану (наприклад, роль користувача).

#### Як це працює?
Якщо у тебе є папка `dashboard/` і в ній слоти `@stats` та `@users`, то `layout.tsx` отримає ці слоти як пропси:

```tsx
export default function Layout({ 
  children, // Це стандартна сторінка page.tsx
  stats,    // Це вміст @stats/page.tsx
  users     // Це вміст @users/page.tsx
}: { 
  children: React.ReactNode, 
  stats: React.ReactNode, 
  users: React.ReactNode 
}) {
  return (
    <div className="layout">
      {children}
      <div className="grid">
        <aside>{stats}</aside>
        <main>{users}</main>
      </div>
    </div>
  )
}
```

---

### 💡 Приклад
Уяви адмін-панель. Зліва — список товарів, справа — деталі обраного.
За допомогою Parallel Routes ти можеш оновлювати праву частину, не перевантажуючи ліву.

---

### ✍️ Практика: Задача 1 (Розминка)
Створимо "Дашборд розробника" в нашому проекті.

1. Створи папку `app/(main)/dashboard`.
2. В середині створи два слоти: `@projects` та `@info`.
3. В кожному слоті створи `page.tsx` з будь-яким текстом.
4. Створи `app/(main)/dashboard/layout.tsx`, який прийме ці слоти та відобразить їх у двоколонковій сітці (Grid).
5. Створи основну сторінку `app/(main)/dashboard/page.tsx` з заголовком "Мій Дашборд".

### 🛡 Стійкість та Streaming (Advanced)

Паралельні маршрути дозволяють робити інтерфейс незалежним:

1. **loading.tsx**: Якщо додати його в папку слота (`@projects/loading.tsx`), цей слот автоматично отримає свій `Suspense`. Весь сайт вантажиться миттєво, а слот чекає на свої дані.
2. **error.tsx**: Якщо додати його в слот, помилка в цьому компоненті не призведе до падіння всього сайту. Користувач зможе бачити інші частини дашборду.

---

### 🚦 Навігація та default.tsx

Це найважливіша частина для розуміння Parallel Routes.

#### Soft Navigation (Link)
Коли ти переходиш за посиланням (наприклад, на `/dashboard/settings`), Next.js намагається оновити тільки ті слоти, які змінилися. Ті слоти, для яких немає нових сторінок, залишаються у своєму **попередньому стані**.

#### Hard Navigation (F5 / Reload)
Коли ти оновлюєш сторінку, Next.js не має "попереднього стану". Він намагається знайти `page.tsx` для поточної адреси в КОЖНОМУ слоті. Якщо його немає — буде помилка 404.

#### Рішення: default.tsx
Цей файл використовується як "fall-back" (запасний варіант) при Hard Navigation. Він показує контент, якщо Next.js не знайшов специфічної сторінки для цього слота за поточною адресою.

### 🔀 Intercepting Routes (Перехоплення маршрутів)

**Intercepting Routes** дозволяють завантажити маршрут з іншої частини сторінки всередині поточного макета. Це ідеально підходить для створення модальних вікон, які мають власну URL-адресу.

#### Навіщо це потрібно?
Користувач клікає на проєкт у дашборді:
1. **Звичайний перехід**: Вся сторінка змінюється на сторінку проєкту.
2. **Intercepting**: Поверх дашборду відкривається модальне вікно з проєктом. Користувач не втрачає контекст (дашборд залишається на фоні), але URL змінюється на `/projects/1`. Якщо користувач оновить сторінку (F5), він потрапить на повноцінну сторінку проєкту.

#### Синтаксис папок
- `(.)` — перехоплює сегмент на тому ж рівні.
- `(..)` — перехоплює сегмент на один рівень вище.
- `(..)(..)` — перехоплює сегмент на два рівні вище.
- `(...)` — перехоплює сегмент від кореня (`app/`).

### ✍️ Практика: Задача 3 (Фінальна для Дашборду)

Ми зробимо так, щоб при кліку на назву проєкту в Дашборді відкривалася модалка через Parallel + Intercepting Routes.

1.  **Створи слот для модалки**: У папці `app/(main)/dashboard` створи слот `@modal`.
2.  **Перехоплення маршруту**: В папці `@modal` створи папку `(.)projects/[id]`.
3.  **Контент модалки**: Створи всередині `page.tsx`. Він буде відображатися ТІЛЬКИ при переході з дашборду.
4.  **Онови Layout**: Додай `{modal}` у `dashboard/layout.tsx`.
5.  **Додай посилання**: У `@projects/page.tsx` зроби назви проєктів посиланнями на `/projects/1`, `/projects/2` тощо.
6.  **Default**: Не забудь створити `app/(main)/dashboard/@modal/default.tsx`, який повертає `null` (щоб модалка була порожньою за замовчуванням).
