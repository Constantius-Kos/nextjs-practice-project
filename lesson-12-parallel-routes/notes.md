# 📝 Нотатки Уроку 12: Parallel Routes

### Запитання та відповіді
**П: Чому тем про loading, error та default.tsx не було у початковій теорії?**
**В:** Ми розбирали це крок за кроком на практиці, щоб краще засвоїти. Теорія тепер оновлена (у файлі THEORY.md) і включає всі ці аспекти для повної картини.

### Клюйові терміни
- **Slots (@folder)** — папки-слоти, які передаються в пропси лейауту. Не впливають на URL.
- **Matched Routes** — коли URL відповідає структурі слота.
- **Default.js** — файл-запобіжник для ситуацій, коли Next.js не знає, що показувати в слоті при навігації.

### 🚦 Видимість папок в URL (Cheat Sheet)
- `folder` -> `/folder` (Видимо)
- `[id]` -> `/123` (Видимо, динамічно)
- `(group)` -> (Невидимо) — тільки для організації
- `@slot` -> (Невидимо) — тільки для Parallel Routes

---

### 🚦 Навігація в Parallel Routes

**З: Чому при кліку на посилання слоти не оновлюються, а при F5 — оновлюються?**
**В:** Це різниця між **Soft** та **Hard** навігацією:
1. **Soft Navigation (Link)**: Next.js намагається зберегти стан інтерфейсу. Якщо в слоті (наприклад, `@projects`) немає папки для нового під-маршруту (наприклад, `/settings`), він залишає старий контент. Це зручно для дашбордів.
2. **Hard Navigation (F5)**: Додаток ініціалізується з нуля. Next.js шукає або точний збіг у папці слота, або використовує `default.tsx`.

**З: Як правильно робити в продакшені?**
**В:** Якщо ти хочеш, щоб при переході в налаштування інші слоти зникали — треба або явно створити там `settings/page.tsx` з `return null`, або не групувати ці сторінки під один лейаут із слотами, якщо вони надто різні.
