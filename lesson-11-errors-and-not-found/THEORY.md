## 📖 Теорія

### 1. error.tsx — Межа помилок (Error Boundary)
Якщо на сервері стався збій (наприклад, база даних недоступна), Next.js шукає найближчий файл `error.tsx`.

**Важливо:** `error.tsx` **ЗАВЖДИ** має бути Client Component (`'use client'`), тому що він має вміти відновлювати роботу сторінки без повного перезавантаження браузера.

**Пропси компонента помилки:**
- `error`: Об'єкт помилки (містить повідомлення та дайджест).
- `reset`: Функція, яка спробує перерендерити сегмент, що "зламався".

### 2. not-found.tsx — Коли ресурс не знайдено
Цей файл рендериться у двох випадках:
1. Користувач ввів URL, якого не існує.
2. Ти сам викликав функцію `notFound()` у коді (наприклад, якщо ID проекту не існує в базі).

---

## 💡 Приклади

### Приклад error.tsx:
```tsx
'use client'

export default function Error({ error, reset }: { error: Error; reset: () => void }) {
  return (
    <div className="text-red-500 border border-red-500 p-4">
      <h2>Щось пішло не так!</h2>
      <button onClick={() => reset()} className="bg-blue-500 text-white p-2 mt-2">
        Спробувати ще раз
      </button>
    </div>
  )
}
```
