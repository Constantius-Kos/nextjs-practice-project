# 📋 Резюме уроку 11: Обробка помилок (error.tsx та not-found.tsx)

### 1. error.tsx — Межа помилок
- Якщо в коді стався збій (500 помилка, збій БД), Next.js перехоплює його і показує контент з `error.tsx`. 
- Це запобігає падінню всього сайту — ламається тільки "проблемна" папка, решта сайту (меню, футер) залишається робочою.

### 2. Чому `'use client'`?
- Файли помилок зобов'язані бути **Client Components**. Це потрібно для того, щоб вони могли працювати після того, як сервер "впав", і надати користувачу кнопку для виправлення ситуації.

### 3. Пропс `reset()`
- Головний інструмент в `error.tsx`. Це функція, яка каже Next.js: "Спробуй ще раз відрендерити цей шлях". Користувачу не потрібно оновлювати сторінку повністю.

### 4. not-found.tsx
- Використовується для створення гарних 404 сторінок. 
- Його можна викликати вручну в коді за допомогою функції **`notFound()`** (наприклад, якщо користувач шукає проект з ID, якого не існує в базі).

### 5. Глобальність vs Локальність
- Можна створити один `app/not-found.tsx` для всього сайту.
- Можна створити специфічний `app/dashboard/error.tsx`, щоб помилки дашборду виглядали інакше, ніж загальні помилки сайту.
