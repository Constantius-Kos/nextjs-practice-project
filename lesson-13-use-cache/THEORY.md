# 📖 Теорія Уроку 13: Директива "use cache" (Advanced)

У Next.js 16 кешування перейшло на нову модель, де ми явно вказуємо, які дані мають бути статичними. Більше не потрібно налаштовувати всю сторінку як статичну — ми кешуємо окремі функції.

### 1. Глибоке розуміння "use cache"
Директива `"use cache"` — це вказівка для компілятора Next.js закешувати результат виконання асинхронної операції. 

**Ключові особливості:**
- **Область дії:** Можна ставити всередині асинхронної функції (кешує лише її) або на початку файлу (кешує всі експортні функції в цьому файлі).
- **Автоматичні ключі:** Next.js автоматично створює ключ кешу на основі аргументів функції. Якщо викликати `fn(1)` і `fn(2)`, це будуть два різні записи в кеші.
- **Всюдихідність:** Працює не тільки з `fetch`, а з будь-яким кодом (запити до БД через Prisma/Drizzle, складні математичні розрахунки тощо).

### 2. Правила серіалізації (Serialization)
Оскільки кеш зберігається у вигляді даних (як правило, у пам'яті або на диску), результати функції мають бути **серіалізованими**.
- **Можна повертати:** Об'єкти, масиви, рядки, числа, булеві значення.
- **Не можна повертати:** Функції, екземпляри класів (з методами), складні об'єкти з циклічними посиланнями.

### 3. Server Components та "use cache"
Ти можеш поставити `"use cache"` прямо всередині Server Component! Це зробить його частину статичною, навіть якщо він знаходиться всередині динамічної сторінки.

```tsx
async function StaticBanner() {
  "use cache";
  return <div>Акція дня: -50% на все!</div>;
}
```

### 4. Порівняння зі старими методами
| Старий метод (v14/15) | Новий метод (v16) | Перевага |
| :--- | :--- | :--- |
| `unstable_cache` | `"use cache"` | Набагато простіший синтаксис та краща продуктивність. |
| `fetch(url, { cache: 'force-cache' })` | `"use cache"` у функції з fetch | Кешується не просто мережева відповідь, а готовий оброблений результат. |
| `export const revalidate = 60` | Директива + `cacheTag` (наст. урок) | Гранулярність: можна оновлювати частину сторінки, а не всю відразу. |

### ✍️ Практичні завдання

#### Задача 1: Розминка
Створи функцію `getProjectStats()` у файлі `lib/db.ts`. 
- Використай `"use cache"`.
- Додай затримку 3 секунди через `setTimeout`.
- Поверни об'єкт `{ total: 10 }`.
- Виведи результат у дашборді. Переконайся, що після першого завантаження сторінка оновлюється миттєво.

#### Задача 2: Основна (Робота з аргументами)
Модифікуй функцію так, щоб вона приймала `userId`. 
- Повертай різну кількість проектів залежно від ID (наприклад, для `id=1` -> 5 проектів, для `id=2` -> 10).
- Викликай функцію двічі у компоненті з різними ID. Подивись на консоль сервера: скільки разів спрацює `console.log`?

#### Задача 3: Челлендж (Компонент-кеш)
Спробуй винести частину верстки дашборду (наприклад, вітальну картку) в окремий компонент і додати `"use cache"` прямо всередину цього компонента. Додай туди `console.log`, щоб перевірити, чи рендериться він повторно при оновленні сторінки.
