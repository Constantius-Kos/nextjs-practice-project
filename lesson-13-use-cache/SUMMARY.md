# 📋 Резюме уроку 13: Директива "use cache"

### 1. Нова модель кешування Next.js 15/16
- `"use cache"` — це директива, яка дозволяє кешувати результати функцій або цілих файлів.
- Вона замінює старі методи типу `unstable_cache` та старий `fetch` кеш.
- Працює на рівні **Data Cache** (зберігається на сервері).

### 2. Область дії (Scope)
- **На рівні функції:** Кешує результат тільки цієї конкретної функції. Ідеально для запитів до БД.
- **На початку файлу:** Кешує результати УСІХ функцій у цьому файлі. Зручно для API-клієнтів.

### 3. Правила серіалізації 📦
- Дані, що повертає функція, мають бути **серіалізованими** (JSON-like: об'єкти, масиви, рядки, числа).
- Не можна кешувати функції, класи або складні об'єкти з методами.
- Якщо дані не серіалізуються — виникне помилка збірки.

### 4. Статичний vs Динамічний контекст
- Функція з `"use cache"` за замовчуванням вважається **статичною** (однаковою для всіх).
- Якщо всередині використовуються `headers()`, `cookies()` або динамічні пропси, Next.js автоматично зробить кеш специфічним для цього контексту (або видасть помилку, якщо кешування неможливе).

---

### 💡 Ключові висновки нашої практики:
1.  **Cache Key**: Аргументи функції автоматично стають частиною ключа кешу. Різні ID = різні записи в кеші.
2.  **Швидкість**: Перший запуск — повільно (захид до БД), наступні — миттєво (читання з диску сервера).
3.  **Experimental**: Для роботи потрібен прапор `cacheComponents: true` (або `dynamicIO`) у `next.config.ts`.
