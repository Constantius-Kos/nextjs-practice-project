# Урок 26: Деплой на Vercel та Production Best Practices

У цьому уроці ми пройшли повний шлях від локального проекту до працюючого сайту в мережі, розібравшись із критичними аспектами безпеки та продуктивності в Next.js 16.

### 🎯 Результати уроку:
1.  **Налаштування Vercel**: Створено та налаштовано проект, підключено приватний GitHub репозиторій.
2.  **Вирішення помилок Build**:
    - Виправлено помилки `Uncached data was accessed outside of <Suspense>`.
    - Додано `loading.tsx` для всіх динамічних маршрутів.
    - Виправлено Type Errors (fallback для аватарок користувачів).
3.  **Production Environment Variables**:
    - Налаштовано OAuth Apps для GitHub та Google (Production версії).
    - Додано `AUTH_SECRET`, `AUTH_GITHUB_ID/SECRET`.
    - Додано `AUTH_URL` для коректної роботи Auth.js.
4.  **Middleware & Security**:
    - Вирішено проблему з префіксами кук `__Secure-` на HTTPS.
    - Реалізовано універсальну перевірку сесії для Local та Production.

### 🛠 Ключові концепції:
- **Partial Prerendering (PPR)**: Next.js 16 вимагає чіткого розмежування статичного та динамічного контенту через Suspense.
- **Cookie Security Prefixes**: На HTTPS-з'єднаннях браузери та бібліотеки (як Auth.js) додають `__Secure-` до назв кук, що потрібно враховувати в Middleware.
- **Prefetching in Production**: Next.js агресивно завантажує дані для посилань у viewport, тому "биті" посилання миттєво викликають 404 у консолі.

### 🏁 Поточний статус проекту:
- Сайт успішно деплоїться на Vercel.
- Авторизація працює через нові Production ключі.
- Блог працює через імпорт JSON для стабільності на серверлесс-середовищі.
